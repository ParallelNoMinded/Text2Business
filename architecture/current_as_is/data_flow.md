# Пайплайн обработки обращения (Data Flow As-Is)

```text
  ┌────────────────────────┐
  │ Входящее сообщение     │ Telegram / Email / Voice / REST
  └───────────┬────────────┘
              │
              ▼
  ┌────────────────────────┐
  │ 1. Guardrails Check    │ Пасс / Отклонение (Инъекция, Спам)
  └───────────┬────────────┘
              │
              ▼
  ┌────────────────────────┐
  │ 2. Fact Extraction     │ GitHub Models / Gemini API / Heuristic Fallback
  └───────────┬────────────┘
              │ JSON Mode: { customer_name, site_info, asset_code, problem_summary }
              ▼
  ┌────────────────────────┐
  │ 3. Client & Site Match │ Поиск в In-Memory DB (`mockDb.ts`)
  └───────────┬────────────┘
              │
              ▼
  ┌────────────────────────┐
  │ 4. Asset Disambiguation│ Разрешение ассетов по открытым заявкам (TC-02)
  └───────────┬────────────┘
              │
              ▼
  ┌────────────────────────┐
  │ 5. SLA & Contract Calc │ Расчет дедлайна (Gold: 60 мин, Standard: 480 мин)
  └───────────┬────────────┘
              │
              ▼
  ┌────────────────────────┐
  │ 6. Decision & Status   │ Confidence >= 0.85 -> AUTO_REGISTERED / HITL Waiting
  └───────────┬────────────┘
              │
              ▼
  ┌────────────────────────┐
  │ 7. 1C OData & UI Sync  │ Проведение документа & Обновление в SPA
  └────────────────────────┘
```

## Шаги пайплайна:
1. **Прием сообщения:** Маршрутизация через Webhook Handler в `server.ts`.
2. **Извлечение:** Запрос к LLM в формате JSON Mode (`response_format: { type: 'json_object' }`).
3. **Сопоставление:** Нахождение контрагента по названию или ИНН, сопоставление объекта обслуживания.
4. **Оценка полноты (Confidence Score):** Если уверенность >= 85% и все факты собраны -> Авто-регистрация. Если данные неполные -> Перевод в `WAITING_DISPATCHER`.
5. **Проведение:** Создание записи `ЗаявкаНаРемонт` и отправка в эмулятор OData 1С.
