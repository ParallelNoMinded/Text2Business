# ADR 003: Выбор Go и Temporal.io для целевого ядра Decision Engine

**Дата:** 2026-06-30  
**Статус:** Принято (Accepted)  

---

## Контекст
Процесс обработки заявки включает долгие паузы ожидания действий человека (Human-in-the-Loop диспетчера), сбои сети, повторные попытки синхронизации с 1С и соблюдение строгих таймаутов SLA.

## Решение
Использовать язык **Go** и фреймворк оркестрации **Temporal.io** для целевого микросервиса Core Decision Engine.

## Почему Go + Temporal.io:
1. **Durable Execution:** Состояние процесса сохраняется автоматически; при сбое сервера процесс возобновляется с той же точки без потери данных.
2. **Saga Pattern:** Удобное управление компенсирующими транзакциями при сбоях 1С.
3. **Высокая производительность Go:** Минимальное потребление памяти и быстрый старт горутин.

## Последствия
- Высокая надежность цепочек обработки обращений.
- Простота поддержки сложных ветвящихся Workflow.
