# ADR-000: Целевая омниканальная событийная архитектура AI-Диспетчера

**Статус:** Принято / Целевое состояние  
**Дата:** 2 августа 2026 г.  
**Автор:** Главный Системный Архитектор  

## 1. Контекст и Проблематика

Существующий монолитный подход обработки входящих заявок (Telegram, Email, Голос, Мессенджеры) требует масштабируемости, высокой отказоустойчивости, возможности работы со звонками в реальном времени (Real-Time STT/TTS) и надёжного управления состоянием бизнес-процессов (Saga / State Orchestration) при интеграции с 1С:ERP и CRM.

## 2. Предлагаемое Решение (Целевая Архитектура)

Переход на микросервисную событийную архитектуру (Event-Driven Architecture) с разделением ответственности:

```text
┌────────────────────────────────────────┐
│       ОМНИКАНАЛЬНЫЙ INGRESS GATEWAY    │
│        (Envoy Gateway)                 │
└──────────────────┬─────────────────────┘
                   │
                   ▼
┌────────────────────────────────────────┐
│   KAFKA / RABBITMQ EVENT BUS (EVENTS)  │
└──────┬──────────────────────┬──────────┘
       │                      │
   ┌───┴──────────────┐   ┌───┴─────────────────┐
   ▼                  │   ▼                     │
┌───────────────────┐ │ ┌───────────────────┐   │
│ SERVICE 1: STT    │ │ │ SERVICE 2: AI     │   │
│ (Yandex / Mochi)  │ │ │ (Python/LangGraph)│   │
└─────────┬─────────┘ │ └─────────┬─────────┘   │
          │           │           │             │
          └───────────┼───────────┘             │
                      ▼                         │
┌────────────────────────────────────────┐      │
│     SERVICE 3: CORE DECISION ENGINE    │◄─────┘
│        (Go / Temporal.io State)        │
└──────────────────┬─────────────────────┘
                   │
                   ▼
┌────────────────────────────────────────┐
│      DATA LAYER & OBSERVABILITY        │
│  • PostgreSQL 18 + pgvector + Redis    │
│  • Arize AI (OTel Metrics)             │
│  • 1C:ERP OData Enterprise Adapter     │
└────────────────────────────────────────┘
```

### Ключевые компоненты целевого контура:

1. **Omnichannel Ingress Gateway (Envoy Gateway):**
   - Единая точка входа для Telegram Webhooks, Email SMTP/IMAP, Telephony SIP/RTP, REST API и 1C OData.
   - Обеспечивает TLS Termination, Rate Limiting, Circuit Breaking и валидацию аутентификации.

2. **Kafka / RabbitMQ Event Bus:**
   - Шина событий для асинхронной буферизации обращения (`InboundMessageReceived`, `TranscriptChunkCreated`, `FactsExtracted`, `DispatchDecisionMade`).
   - Изолирует сетевые пики нагрузок от внутренних обработчиков.

3. **Service 1: STT & Speech Service (Yandex SpeechKit / Mochi):**
   - Потоковая расшифровка аудиопотока и телефонных звонков (gRPC Streaming).
   - Нормализация текста и удаление акустических шумов.

4. **Service 2: Perception & AI Engine (Python / LangGraph + vLLM / GitHub Models):**
   - Оркестрация мультиагентных сценариев извлечения фактов (ReAct agent, JSON Schema validation).
   - Извлечение атрибутов: Клиент, Объекты/Активы, Код номенклатуры, Описание поломки, Срочность.

5. **Service 3: Core Decision Engine (Go / Temporal.io State Machine):**
   - Гарантированный запуск workflow обработки заявок с поддержкой долгих Human-in-the-Loop (HITL) пауз.
   - Взаимодействие с диспетчером при недостающих фактах (Completeness Check) и формирование проводки в 1С.

6. **Data Layer & Observability:**
   - **PostgreSQL 18 + pgvector:** Реляционное хранилище заявок, клиентской базы и векторный поиск похожих инцидентов.
   - **Redis:** Кэш сессий и быстрые блокировки (Distributed Locking).
   - **1C:ERP Enterprise OData Adapter:** Адаптер для двусторонней синхронизации документов "ЗаявкаНаРемонт" и "ЗаказНаряд".
   - **Arize AI & OpenTelemetry:** Мониторинг качества галлюцинаций LLM, задержек и трейсов запросов.

## 3. Последствия и План Миграции

- Повышение отказоустойчивости до 99.99%.
- Возможность обработки 10,000+ обращений в минуту без потери данных.
- Полная прозрачность аудита благодаря Temporal.io.
