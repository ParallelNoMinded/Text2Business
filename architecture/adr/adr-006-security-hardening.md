# ADR 006: Усиление безопасности прототипа (токен, dry-run, PII, guardrails)

**Дата:** 2026-08-06
**Статус:** Принято (Accepted)

---

## Контекст
Прототип Text2Business разворачивается как демонстрационный стенд и не является production-системой, однако чек-лист тестового задания требует закрыть базовые классы угроз:
- несанкционированные мутации данных (любой HTTP-запрос мог создать тикет);
- утечка открытых заявок и токенов через API (GET /api/webhooks/dispatch отдавал весь массив open_tickets; GET /api/llm/config — превью токена);
- PII (телефоны, ИНН, email) в логах, трейсах и LLM-промптах;
- prompt injection и подмена SLA через текст обращения;
- декоративные «секреты» и localStorage-хранение токена во фронтенде.

## Решение
1. **Защита API токеном:** все мутирующие и чувствительные эндпоинты требуют заголовок `X-Dispatch-Token` (env `DISPATCH_TOKEN`, dev-дефолт `dev-dispatch-token`). Проверка — middleware `requireDispatchToken` (server.ts).
2. **Никаких мутаций из webhook'ов:** telegram/email/telephony/dispatch webhook-и и long polling выполняют только dry-run предпросмотр (`is_dry_run=true`); единственная точка записи в БД — `POST /api/commit-ticket` с проверкой, что `site_id`/`asset_id` существуют в реестре.
3. **Маскирование PII:** функция `maskPii` (телефоны, ИНН, email) применяется к логам (`pushLog`), деталям trace-шагов и телу LLM-запроса; канал в логах нормализуется к допустимому множеству.
4. **Валидация входа:** лимит тела JSON 100kb, `MAX_TEXT_LENGTH=4000`, whitelist каналов, схема-проверка ответа LLM (`normalizeParsedFacts`).
5. **Guardrails и данные != инструкции:** усиленный детерминированный `checkGuardrails` (нормализация текста, расширенные RU/EN сигнатуры) + явное правило в system-инструкции LLM.
6. **Фронтенд:** токены больше не пишутся в localStorage (GitHub-токен — только память React, dispatch-токен — sessionStorage); удалены хардкод-«секреты` (`sec_app_pass_99812`, `tel_sec_key_88192`).

## Последствия
- Демо-стенд требует заголовок токена у всех вызовов API; для локальной разработки дефолт задокументирован в README и .env.example.
- Webhook-интеграторы получают только предпросмотр решения; реальная запись — действие оператора HITL (осознанный human-in-the-loop).
- В production-контуре (см. ADR-000) токен заменяется на полноценную аутентификацию (OIDC/mTLS) и подпись webhook-ов.
